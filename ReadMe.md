# Alternative Starting Inventory Library

## Overview

This library exposes utility APIs intended for mod authors to integrate alternate starting decks, relics, and
inventories. It is not a full standalone mod.

## Usage

Reference the compiled assembly (DLL) from your project and call the helpers found in
`AlternativeStartingInventory.AlternativeStartingInventoryCode.Utils`.

### What this library is for

Use this library when you want to register a custom starting inventory for a character without building the entire
system yourself. The main entry points are:

- `StartingInventory`: describes the inventory data to apply
- `StartingInventoryManager`: registers, fetches, and removes inventories for a character

### Basic workflow

1. Create a `StartingInventory` for a specific character.
2. Set the properties you want to override, such as HP, gold, cards, relics, and potions.
3. Register it with `StartingInventoryManager`.
4. Optionally listen to the inventory events for custom logic before or after the inventory is applied.

### Minimal example

```csharp
using MegaCrit.Sts2.Core.Models;
using AlternativeStartingInventory.AlternativeStartingInventoryCode.Utils;

// Obtain a CharacterModel (example: from ModelDb)
CharacterModel characterModel = ModelDb.Character<Ironclad>();

// Create a new StartingInventory (id must be unique per character)
var inventory = new StartingInventory(characterModel, $"{ModPrefix}-my_custom_start")
{
    Hp = 80,
    Gold = 99,
    Cards = [
        ModelDb.Card<Tremble>(),
        ModelDb.Card<SpoilsOfBattles>()
    ],
    Relics = [
        ModelDb.Relic<BoundPhylactery>()
    ],
    Potions = [
        ModelDb.Potion<HeartOfIron>()
    ]
};

// Register the inventory for the character
StartingInventoryManager.AddNewInventoryForCharacter(characterModel, inventory);
```

### Common properties


```csharp
var inventory = new StartingInventory(characterModel, $"{ModPrefix}-starter")
{
    Hp = 100,
    Gold = 100,
    Cards = [
        ModelDb.Card<Tremble>(),
        ModelDb.Card<SpoilsOfBattles>()
    ],
    Relics = [
        ModelDb.Relic<BoundPhylactery>()
    ],
    Potions = [
        ModelDb.Potion<HeartOfIron>()
    ],

    // Lock the inventory behind specific epochs.
    RequiredEpochs = [
        EpochModel.Get<Defect3Epoch>(),
        EpochModel.Get<Defect7Epoch>()
    ],

    // Optional display metadata.
    Name = "Locked Starter Deck",
    Description = "Unlocked after progressing through specific epochs.",
    UnlockText = "Requires a specific epoch"
};
```

### Managing inventories

```csharp
 // Register the inventory for the character
StartingInventoryManager.AddNewInventoryForCharacter(characterModel, inventory);

// Fetch all inventories registered for a character.
var inventories = StartingInventoryManager.GetStartingInventoriesForCharacter(characterModel);

// Remove a previously registered inventory by id.
StartingInventoryManager.RemoveStartingInventoryForCharacter(characterModel, $"{ModPrefix}-my_custom_start");
```

### Events

`StartingInventory` exposes two event argument types that you can use to hook into the lifecycle.

#### 1. `PlayerInventoryEventArgs`

Used for inventory application lifecycle hooks such as before/after the player data or inventory is applied.

```csharp
var inventory = new StartingInventory(characterModel, $"{ModPrefix}-events")
{
    Hp = 80,
    Gold = 99
};

inventory.BeforePlayerDataApply += (_, e) =>
{
    // e.Player is available here if you want to modify the player before data is applied.
};

inventory.AfterPlayerInventoryApply += (_, e) =>
{
    // e.Player is available here if you want to react after the inventory was applied.
};
```

Available events in this group:

- `BeforePlayerDataApply`
- `AfterPlayerDataApply`
- `BeforePlayerInventoryApply`
- `AfterPlayerInventoryApply`

#### 2. `AddContentEventArgs`

Used when the inventory wants to add extra UI content to the character select or deck info presentation.

```csharp
inventory.DisplayContentForCharacterSelect += (_, e) =>
{
    // e.Owner is the control that should receive the extra content.
};
```


## Limitations

- Only shows the first 25 cards / relics (Configurable by the user up to 100)

### Known Bugs

- Multiplayer
    - Does not sync inventory until the first combat is triggered
